## How the Script Works

The automation script demonstrates the complete Visual Layer custom metadata API workflow:

1. **Reads your CSV metadata** and the exported `metadata.json` file from Visual Layer
2. **Creates filename-to-media_id mapping** using the Visual Layer export data
3. **Analyzes CSV fields** and automatically detects data types (string, float, datetime, enum)
4. **Creates custom metadata fields** in Visual Layer via API calls
5. **Uploads metadata values** for each field using the proper JSON format
6. **Monitors upload progress** and reports completion status

## Prerequisites

Before using the script, ensure you have:

1. **Visual Layer on-premises installation** (script designed for no-authentication environments)
2. **Dataset in READY state** in Visual Layer
3. **Python environment** with required packages: `pandas`, `requests`
4. **Two input files**:
   - Your CSV file containing metadata
   - `metadata.json` file exported from Visual Layer

### Getting the metadata.json File

The script requires a `metadata.json` file exported from Visual Layer. This file contains the critical mapping between your image filenames and Visual Layer's internal `media_id` values.

<Steps>
  <Step title="Export your dataset">
    In Visual Layer, navigate to your dataset and use the export functionality to download the metadata.json file
  </Step>
  <Step title="Locate the metadata.json file">
    The export will include a `metadata.json` file containing all image-level metadata with `media_id` and `file_name` fields
  </Step>
  <Step title="Place in same directory">
    Keep the `metadata.json` file accessible to the script along with your CSV metadata file
  </Step>
</Steps>

## CSV File Format

Your CSV file should include a filename column and your custom metadata fields:

```csv
filename,temperature,location,quality_score,status
image001.jpg,23.5,warehouse_a,0.95,approved
image002.jpg,24.1,warehouse_b,0.87,pending
image003.jpg,22.8,warehouse_a,0.92,approved
```

**Requirements:**
- Include a column that matches filenames in your Visual Layer dataset
- Supported column names: `filename`, `file_name`, or `image_filename`
- All other columns will be processed as custom metadata fields
- Empty values are automatically skipped during upload

## Field Type Detection

The script automatically detects field types based on your data:

| Data Type | Detection Logic | Example Values |
|-----------|----------------|----------------|
| **float** | Contains decimal points or scientific notation | `23.5`, `1.2e-3` |
| **datetime** | Recognizable date/time formats | `2024-01-15`, `2024-01-15 14:30:00` |
| **enum** | Categorical data with ≤10 unique values | `approved`, `pending`, `rejected` |
| **string** | Default for all other data | `warehouse_a`, `batch_12345` |

<Tip>
You can customize the field detection logic in the `analyze_csv_fields()` function to match your specific needs. For example, force certain fields to be enum types or skip fields that shouldn't be uploaded.
</Tip>

## Troubleshooting

### Common Issues

**No filename mappings created:**
- Verify your CSV filename column matches files in the Visual Layer dataset
- Check that column is named `filename`, `file_name`, or `image_filename`
- Ensure the `metadata.json` file is from the correct dataset export

**Field creation fails:**
- Confirm your Visual Layer instance is accessible at the specified URL
- Check that the dataset ID is correct and the dataset is in READY state
- Verify you have sufficient permissions for the dataset

**Upload timeouts:**
- Large datasets may take time to process
- The script waits indefinitely - you can interrupt with Ctrl+C if needed
- Check Visual Layer logs for any processing errors

**Type conversion errors:**
- Review the automatic field type detection results
- Customize the `_convert_value()` function for your data formats
- Consider preprocessing your CSV to clean data values
