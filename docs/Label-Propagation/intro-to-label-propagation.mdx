<Card title="How this Helps" icon="lightbulb">
  Label propagation enables teams to rapidly scale annotation efforts by automatically labeling large datasets using only a small set of example images. This is particularly valuable for:

  - ML/CV teams - quickly create high-quality training datasets
  - data scientists - efficiently prepare and validate datasets for your own model development
  - analysts - generate labeled datasets for insights and reporting with minimal manual effort

Label propagation enables users to automatically generate labels across a dataset using minimal manual input. This is especially useful for teams looking to accelerate dataset preparation, reduce annotation costs, and maintain consistent labeling quality across large image collections - both for training your own business models and data exploration alike.

## Key Terminology

Understanding these core concepts is essential for successful label propagation:

**Label** is the category or classification you want to assign to your data. Think of it as the answer to "what type is this?" Labels are the actual classifications like "positive," "negative," "spam," "not spam," "urgent," "routine." They're the end goal of your entire process.

**Class** represents each distinct type of label in your classification system. If you're building a sentiment analyzer, your classes might be "positive," "negative," and "neutral." Classes are the buckets that organize your labels. You need at least two classes for any classification task, and each class needs enough examples to teach the system what belongs in that category.

**Seed** refers to the initial labeled examples you provide for each class. These are your training examples that show the system what each class looks like in practice. Seeds are the foundation that makes everything else possible. Without good seed examples, the automatic labeling won't know what patterns to look for.

## How Label Propagation Works

The label propagation feature in Visual Layer combines automated processing with human oversight to efficiently label large datasets. The algorithm uses a confidence-based approach to iteratively label your dataset through the following process:

<Steps>
  <Step title="Seed Creation">
    You provide labeled examples for each class (minimum 5 examples per class). The system uses these examples to learn the characteristics of each class and establish the foundation for automated labeling.
  </Step>
  <Step title="Enhanced Embedding Processing">
    For optimal results, an enhanced embedding process may run automatically during dataset creation that:

    - Runs automatically during dataset creation when enabled
    - Learns the distribution patterns of your specific dataset
    - Creates enhanced embeddings that are more tailored to your data
    - Can be a lengthy process for large datasets
  </Step>
  <Step title="Confidence-Based Labeling">
    The algorithm analyzes your seed examples and begins labeling images with confidence scores for each possible class. Each image receives percentage scores for all classes using two types of confidence:

    - **Label Detection Confidence**: Probability that an image belongs to a specific class
    - **Mislabel Confidence**: Internal algorithm metric for quality control (not exposed to users)

    Example scoring:

    - Class A: 85% confidence
    - Class B: 12% confidence
    - Class C: 3% confidence
  </Step>
  <Step title="Automatic Assignment">
    Images with high confidence scores (typically \>80%) are automatically labeled and marked as complete without requiring human review.
  </Step>
  <Step title="Review Queue Creation">
    Images with low confidence scores are sent to review in batches for human feedback. The system will ask for feedback on a maximum of 10% of your total dataset.
  </Step>
  <Step title="Review and Refinement">
    You review the automatically generated labels in batches, providing feedback to improve accuracy through approval, correction, or reassignment actions. Label propagation stops and waits for your feedback each time a review batch is created.
  </Step>
  <Step title="Internal Model Generation">
    Visual Layer's system generates an internal trained model based on your seed examples and feedback. This model can be reused for future label propagation tasks on new data within the same dataset context.
  </Step>
</Steps>

<Note>
  **Process Behavior**: Label propagation is semi-automatic and will not continue without human input. You should complete all review items before submitting the final classifications. This ensures the model learns the correct classifications.
</Note>

## Best Practices

To maximize success with Label propagation, consider these recommended approaches for optimal results.

- **Seed Quality**: Provide diverse, high-quality examples for each class to help Visual Layer's algorithm learn accurate patterns for automatic labeling
- **Review Thoroughly**: Take time to review automatically generated labels, especially for items requiring attention
- **Iterative Improvement**: Run multiple iterations of Label propagation on the same dataset to refine results. Each iteration allows you to adjust your seed examples, provide additional feedback during the review phase, and improve overall labeling accuracy over time
- **Progress Monitoring**: Regularly check progress indicators to ensure your dataset is becoming ready for training your own models

## Limitations and Technical Requirements

Understanding current system limitations and technical requirements helps ensure successful Label propagation implementation.

### Current Limitations

- **No Stacking**: Visual Layer doesn't currently enable partial updates to datasets.
- **Feature Interactions**: Running Label propagation on datasets previously labeled via an enrichment model may cause rendering issues or duplicated items.

### Algorithm Validation

- **Precision/Recall**: Achieved 0.9863/0.9863 precision and recall on validation datasets
- **Determinism**: Small variations in embeddings (~0.0001) may occur due to machine/environment differences, but do not affect overall performance
- **Consistency**: Results maintained within 0.1-0.2 margin across different implementations
